# M5 Chunk 7: governed repair disposition

## Discovery and ownership

The existing [RepairAuthorityRepository](../../src/core/storage/repositories/RepairAuthorityRepository.ts) owns immutable repair authority. [GovernedRepairDecisionService](../../src/core/healing/GovernedRepairDecisionService.ts) establishes the trusted-local explicit human declaration pattern. [RepairEffectivenessAuthority](../../src/core/storage/RepairEffectivenessAuthority.ts) revalidates the exact committed comparison and its complete lineage. These owners are extended; no competing App Model or general lifecycle state machine is introduced.

[TestSetRepository](../../src/core/storage/repositories/TestSetRepository.ts) defines current as the highest materialized revision. Chunk 4 already creates a canonical revision. There is no separate accepted-revision pointer to adopt. Legacy [CoverageGapRepository](../../src/core/storage/repositories/CoverageGapRepository.ts) closes a different mutable gap object, and the [project domain lifecycle](../../src/core/domain/tdUi062b.ts) governs projects rather than repair attempts. Neither represents this new boundary.

## Frozen contract

1. **Input authority.** Require the exact committed original failed Result and diagnostic; approved proposal, human decision and supersession; materialized Definition/Test Set and repair origin; governed AFTER acceptance, terminal execution and available Run/Result/link; and committed Chunk 6 effectiveness evidence. Input identifies the comparison request and expected comparison ID/hash, origin ID, supersession ID/hash and resulting Definition authority. Persisted facts supply evidence; submitted evidence envelopes cannot replace them. Terminal missing Run/Result/diagnostic preserves exact nulls. Active transient comparisons and uncommitted prerequisites refuse.
2. **Authorization.** Eligibility is deterministic and read-only. Every persisted disposition requires an explicit human declaration with actor ID, decision ID, decision time and allowed action. This follows the existing trusted-local service boundary; it preserves the caller's human declaration and does not authenticate a remote person or infer approval from AI output. Effectiveness evidence alone cannot transition authority.
3. **Confirmed.** REPAIR_CONFIRMED permits only resolve_bounded_repair, producing bounded_repair_resolved. This resolves the exact observed selector/action attempt. It never declares overall test success, mutates the canonical Result, or adopts a different current revision. A failed later oracle remains failed.
4. **Not confirmed.** REPAIR_NOT_CONFIRMED permits only close_unsuccessful, producing repair_unsuccessful. Preserve all prior evidence and materialized history. No automatic second repair, rollback or revision mutation occurs.
5. **Inconclusive.** INCONCLUSIVE permits only record_inconclusive, producing manual_followup_required. This records an explicit unresolved investigation state with no success claim. No task, retry, execution or escalation job is launched. Missing required integrity authority refuses rather than becoming this factual outcome.
6. **Immutability.** Append a new disposition record only. Never rewrite original/materialized Definitions or Test Sets, original/rerun Executions/Results/diagnostics, App Models/support, proposal, human decision, supersession, repair origin, rerun link, or effectiveness evidence. Update/delete/replace of disposition evidence refuses. Existing current Test Set selection and overall Results are unchanged.
7. **Exact lifecycle.** The subject is one exact comparison attempt: project + original Result + governed AFTER Execution + comparison policy. Its origin, supersession, source/candidate App Model revisions/support, materialized Definition and complete execution/result provenance must match. This is not an origin-global lock and does not revoke separately human-authorized rerun semantics already established by Chunk 5.
8. **Replay.** The same exact identity, declaration and freshly revalidated evidence returns the same canonical disposition bytes. Existing locale-independent canonicalJson/canonicalJsonSha256 owns new hashes. No wall-clock default, probabilistic confidence or random derived identity is introduced.
9. **Conflict.** One authoritative disposition per exact comparison/AFTER execution. Different decision/action/actor/time, IDs, expected hashes or evidence for that subject fails closed, including attempts to overwrite confirmed, unsuccessful or inconclusive disposition with another state. Replay is not a divergent duplicate insertion.
10. **Stale and tampered refusal.** Re-read committed comparison, reconstruct current persisted lineage using the existing comparison owner, and perform its fresh authority inspection. Mismatched or missing source/candidate support, identities, hashes, expected revisions or configuration authority refuse. Never accept an arbitrary recomputed caller envelope. The repository owns BEGIN IMMEDIATE through commit/rollback; Kysely transactions and manually opened caller transactions refuse before writes, without rolling back caller-owned work. Failed persistence leaves no partial authoritative state.
11. **Provenance and reads.** Disposition preserves explicit human declaration and exact comparison reference/hash/classification, complete Chunk 6 provenance, original/rerun Result and execution, materialized Definition/Test Set, repair origin, supersession, proposal and earlier human approval. Public read/eligibility surfaces consume persisted authority and expose missing evidence explicitly; they do not manufacture disposition or repair data on read. SQL admission derives required facts from actual committed rows. Native and WASM persistence use the same contract.
12. **No next repair.** Disposition invokes no proposal generator, repair eligibility re-entry, human approval, materializer, executor or generalized healing. The allowed next states are only the bounded terminal/manual-followup records above. No route, oracle, subject, target, action-kind, credential or infrastructure repair is added.

## Scope and proof obligations

The repository privately grants exact-payload insertion admission only during its validated transaction. The native/WASM SQL admission function captures the actual root database owner; its identity does not follow later global workspace changes. Grants are removed after insertion or failure, have no exported writer, and do not constitute remote human authentication. Independent SQL reconstruction still checks the entire evidence chain. Other database owners, including distinct in-memory databases, cannot inherit a grant; custom cloned handles without the registered root owner fail closed.

The minimum additive slice is disposition contract/service, storage derivation and migration 040, existing RepairAuthorityRepository and database/migration registrations, read projection where needed, focused hostile tests and this document. Existing frozen M5 schemas and classification semantics remain unchanged. Proofs cover all three factual outcomes, later-oracle failure, pending/terminal gaps, public/repository/SQL boundaries, exact lineage, historical preservation including rerun links and comparisons, caller transactions, replay/conflict, faults/rollback, populated native/WASM 039-to-040 upgrades, reopen/replay, and actual plain-Node Playwright reporter/browser startup. Full applicable local gates and independent Work review are required before CHECKPOINT_READY. Unavailable live storage remains uncertified.
