## Frozen contract

1. **Input pair.** Public input contains project ID, original Result ID, governed AFTER Execution ID, expected AFTER Result ID (explicit null for an evidence gap), and fixed comparison policy version. The repository derives actual objects. BEFORE is the original immutable non-passing Result and exact diagnostic named by Chunk 5. AFTER is the sole governed attempt/item Result, exact diagnostic and rerun link; terminal evidence gaps preserve nulls.
2. **Exact pairing.** Revalidate the existing acceptance binding, original evidence, committed materialization, source and candidate revisions/support, approval/supersession/proposal, historical accepted Definition identities, manifest/plan, Run and reciprocal Result/rerun linkage. No latest-row selection, arbitrary pairing or caller-generated evidence is accepted.
3. **Target.** Evaluate only the source/candidate data-test selector at the same governed source subject, element, action and target subject. The source diagnostic must demonstrate target absence or an uncompleted action at that exact source target. Source oracle/authentication/navigation failures do not prove a targeted selector failure.
4. **States.** Exactly `REPAIR_CONFIRMED`, `REPAIR_NOT_CONFIRMED`, `INCONCLUSIVE`, each with a deterministic reason. Authority errors refuse; they are not effectiveness judgments. No probability or confidence score.
5. **Confirmed.** Valid terminal lineage and consistent canonical Result/diagnostic evidence; successful prerequisites on the governed route; approved target observed with cardinality one; bounded click completed; no contradictory evidence. Confirmation describes the observed selector/action effect, not general causal proof or entire-test success.
6. **Not confirmed.** The approved selector observes zero targets, or the same bounded action failure class observed BEFORE remains AFTER. Reasons distinguish target absence from action failure. Generic interaction failure does not establish that the selector itself is broken.
7. **Inconclusive.** Earlier unrelated failure, target not reached, ambiguous cardinality, different action failure, or terminal missing Result. An active execution returns transient nonpersistent INCONCLUSIVE, preventing an immutable comparison from freezing temporary absence. Missing diagnostics for a persisted Result, mismatched identities/hashes or malformed lineage refuse. A terminal missing-Result diagnostic is bound when present; absent diagnostic remains null, including the existing [`terminalizeCancellation`](../../src/core/execution/ExecutionRunCoordinator.ts) path with an admitted cancelled Run. Missing diagnostic for an existing Result still refuses.
8. **Broader outcome.** A later oracle mismatch may coexist with confirmed target/action evidence. The canonical overall Result remains failed; comparison neither changes aggregation nor asserts that oracle failure is causally unrelated. Cancelled/interrupted lifecycle preserves already committed evidence; absent evidence is never invented.
9. **Immutability.** Append comparison authority only. BEFORE/AFTER Results, diagnostics, Definitions, Test Sets, App Models and upstream repair records remain unchanged. No historical backfill.
10. **Replay.** Project + original Result + governed AFTER Execution + policy identify one comparison. Exact expected Result identity must agree. Identical persisted evidence returns identical canonical bytes. Terminal-event identity and exact evidence references bind the observation; wall-clock comparison time is not semantic identity.
11. **Conflict.** A conflicting identity, expected Result, stored comparison payload/hash or source evidence refuses with no partial writes. The repository owns the transaction; caller-owned transactions and caller-produced comparison envelopes are not write authority. SQLite insertion guards derive expected comparison from actual rows; update/delete/replace refuse.
12. **Provenance.** Comparison -> exact AFTER Result/diagnostic (or explicit terminal gap) -> governed Execution/acceptance and rerun link -> materialized Test Set/Definition -> supersession -> human approval/proposal -> exact original Result/diagnostic/source authority. Preserve both exact endpoints/revisions and canonical terminal history. Chunk 5 does not record an independent diagnostic creation time or diagnostic-caused approval; comparison does not invent either.

## Mandatory behavior and validation

A/B/L: valid pair, exact lineage and full provenance through canonical public/repository reads. C/E/F/G/H: targeted-only deterministic state matrix, prerequisite failures and later oracle mismatch. D/I/J/K: immutable historical rows, malformed/stale input refusal, deterministic replay/conflict and rollback. M: no runner, proposal, approval or materialization invocation. New tests exercise public and repository input boundaries, persistence invariants, reporting reads, cancellation/incompletion, native/WASM migration 038->039 and historical preservation. Frozen M5 schemas remain unchanged.

Product scope is limited to comparison service/contract, existing repair repository and Results projection, additive comparison persistence and migration registration, focused tests and this contract. No UI, next repair, generalized healing, route/oracle/credential/infrastructure repair, or retry policy is added. Live storage unavailable remains uncertified; disposable proofs do not substitute for it.
